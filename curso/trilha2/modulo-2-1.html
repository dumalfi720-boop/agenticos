📜 CLAUDE.md as traffic control

It's not a diary — it's the document that guides the agent's every decision. CLAUDE.md is persistent memory that transforms isolated sessions into a coherent system.

🎯 What is CLAUDE.md

Every time you open Claude Code in a project, it looks for a file calledCLAUDE.mdand reads it automatically, before anything else. This file is your central identity document — it defines who the agent is in that context, what rules to follow, what to never do, and the current state of the project. Without it, each session starts from scratch. With it, the agent knows exactly where it is and how to operate.

📌What CLAUDE.md loads

  • •Agent identity— name, role, persona, tone of voice.
  • •Business context— what the project is, who the users are, what the objective is.
  • •Non-negotiable rules— what to never do, what to always do.
  • •Decisions already taken— so as not to revisit what has already been resolved.
  • •Technical standards— stack, code conventions, folder structure.

👤Marco, fashion e-commerce

"Before CLAUDE.md, I spent 10 minutes at the beginning of each session explaining the project. Afterwards, the agent already knew everything — stack, tone, what the product was, what the variant was. Immediate gain."

2

🏗️ Structure of a useful CLAUDE.md

A CLAUDE.md without structure becomes a logbook — it grows without criteria and loses signal in the noise. A CLAUDE.md with a clear structure is aoperating manual: any agent who reads it knows exactly how to operate. The structure doesn't have to be rigid, but it does need to be intentional.

Recommended sections

  • # Identity— who I am, role, tone of voice, standard language.
  • # Project Context— what is it, stack, key folder structure.
  • # Non-Negotiable Rules— NEVER / ALWAYS. Maximum 10 items, objectives.
  • # Decisions Made— architectural choices already resolved + reason.
  • # Current Status— what is in progress, what is blocked.
  • # Personas— target user, key stakeholders (optional).

✓ Good CLAUDE.md

  • ✓Clear sections with headers
  • ✓Short, actionable rules
  • ✓Concrete examples
  • ✓Less than 500 tokens
  • ✓Updated after each recurring error

✗ CLAUDE.md problematic

  • ✗Long paragraph without structure
  • ✗Duplicates the entire README
  • ✗Commit changelog
  • ✗More than 2000 tokens
  • ✗Vague rules ("be careful")
3

🌳 Hierarchy: global → project → local

Claude Code supports three levels of CLAUDE.md that cascade together. THEglobalstay in~/.claude/CLAUDE.mdand defines rules that apply to all projects. THEprojectit sits at the root of the repository and defines specific context. THElocationit stays in subfolders and overwrites only in that scope.

🌳Cascade by CLAUDE.md

  • ~/.claude/CLAUDE.md— global rules: language, style, universal prohibitions.
  • project/CLAUDE.md— project context: stack, business rules, personas.
  • project/subfolder/CLAUDE.md— local override: specific rules for that area.

More specific rule wins. Location overwrites project; project overwrites global.

💡Practical tip — Sally, legal office

Sally has the overall: "always respond in formal English". In client X's project there is: "reply in Portuguese". The agent in project X uses Portuguese — no conflict, no confusion. Cascade works like CSS: specific wins.

4

📐 Tone, style and non-negotiable rules

The non-negotiable rules are the agent’s DNA — what he does inallsituations, without depending on the prompt. They are guardrails that protect against recurring errors, quality deviations and behaviors that you have already learned with difficulty that need to be blocked. Write them as direct commands: NEVER, ALWAYS, REQUIRED.

Examples of effective rules

  • Tone:"Always respond in Portuguese. Never use informal language with customers."
  • Code:"Never commit directly to main. Always create a feature/ branch."
  • Data:"Never read /secrets/. Never write outside of /src/ without approval."
  • Quality:"Always run tests before proposing PR. Never silence errors with empty try/catch."
  • Format:"Always use 2 spaces of indentation. TypeScript strict mode required."

📊 Rule of 10

Maintain a maximum of 10 non-negotiable rules per CLAUDE.md. More than that, the signal is diluted. If you have 20 rules, probably half are redundant or should be a code convention — not an agent rule.

5

🚫 What NOT to put

CLAUDE.md is read inall sessions, in full, before any work. Each token you place has a real cost in time and money. A CLAUDE.md inflated with low-value content is literally money burned in overhead, every session. The discipline of keeping the document lean is as important as keeping it updated.

✗ Does not belong to CLAUDE.md

  • ✗Changelog/history of old decisions
  • ✗Credentials, tokens, passwords (NEVER)
  • ✗Extensive technical documentation
  • ✗Duplicate of README or docs/
  • ✗Lists of all project files
  • ✗Instructions for a single one-off task

✓ Belongs to CLAUDE.md

  • ✓Agent identity and role
  • ✓Rules that apply to every session
  • ✓Architectural decisions + reason
  • ✓Minimal stack and conventions
  • ✓What's in progress now
  • ✓Links to relevant Silver Platters

⚠️Critical Alert

Never put credentials, API keys or passwords in CLAUDE.md. The file normally goes into git. Use environment variables or secret vault. An accidental leak costs much more than any convenience.

6

🔄 Evolution of CLAUDE.md

CLAUDE.md is not a document that you write once and forget about — it is aliving organism. Every time the agent makes a recurring error, you add a rule. Every time an architectural decision is made, you record it. Each time the project changes direction, you update the context. The maturity of CLAUDE.md directly reflects the maturity of its agentic system.

Evolution cycle

  • 1. Recurring error detected→ adds non-negotiable rule to CLAUDE.md.
  • 2. Decision made→ records in "Decisions Made" with reason.
  • 3. CLAUDE.md grows too much→ cleans: removes what is not universal, moves to Silver Platters.
  • 4. Project changes phase→ updates "Current State" and "Context".
  • 5. New agent joins the project→ reads CLAUDE.md and is operational in minutes.

💡CLAUDE.md in version control

Versioning CLAUDE.md in git is mandatory. Changes to the agent's identity document must be reviewed — in the same way as changes to critical code. A PR that changes the agent's non-negotiable rules deserves the same attention as a PR that changes authentication.
