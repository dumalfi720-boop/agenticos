📖 What is AGENTS.md

If CLAUDE.md is a document specific to the Anthropic ecosystem, theAGENTS.mdis the industry's answer to the same need — a standardized file that any code agent can read. Started as a community standard and adopted by the Linux Foundation in 2025, AGENTS.md is the "README for machines": it provides project context, build steps, conventions and constraints so that it works in OpenAI Codex, Google Jules, Cursor, Factory and any agent that follows the standard.

🌐Why an open standard matters

  • •Portability— write once, works on multiple agents.
  • •No vendor lock-in— does not tie your project to a single provider.
  • •Ecosystem—contributions from OpenAI, Google, Anthropic, Cursor, and others.
  • •Governed evolution— Linux Foundation guarantees open change process.

📊 Adoption in 2026

  • OpenAI Codex— official support since launch (May/2025)
  • Google Jules— adoption confirmed with A2A (Apr/2025)
  • Cursor, Amp, Factory— native support for AGENTS.md
  • agents.md— official website with spec, examples and guides
  • Linux Foundation— governance since Dec/2025

🆚 CLAUDE.md vs AGENTS.md

The two documents have the same objective — to give context to the agent — but they differ in scope and audience. THECLAUDE.mdis Anthropic-specific: read by Claude Code, can use Claude's own features and syntax. THEAGENTS.mdIt is vendor-neutral: it works on any compatible agent. In 2026 multi-agent projects, having both is common and recommended.

CLAUDE.md

  • •Read by Claude Code
  • •Identity, rules, personas
  • •Can reference skills and hooks
  • •Hierarchy: global/project/local
  • •Vendor: Anthropic

AGENTS.md

  • •Read by Codex, Jules, Cursor...
  • •Build, test, technical conventions
  • •Technical context of the project
  • •Override chain per folder
  • •Vendor: Linux Foundation (open)

💡Recommended strategy

Keep both. AGENTS.md loads the portable technical context (build, test, stack). CLAUDE.md carries Claude-specific identity, business rules and resources. If there is a conflict, CLAUDE.md prevails over Claude Code.

🔗 Codex instruction chain

OpenAI Codex implemented a hierarchical instruction chain that mirrors the logic of CLAUDE.md, but with its own nomenclature. Understanding this chain is useful for any team that uses multiple agents — and theAGENTS.md patternserves as a common denominator between them all.

Chain of precedence in the Codex

  • 1. AGENTS.override.md (global)— user's personal rules, maximum precedence.
  • 2. AGENTS.md (project)— repository context and conventions.
  • 3. AGENTS.md (subfolder)— local override for specific area.
  • 4. Agent System Prompt— default fallback if no files found.

Same logic as CSS: more specific wins. Closer to the file in question, more relevant.

CSS Analogy

Think of AGENTS.override.md as!important: overwrites everything. The project's AGENTS.md is the page's stylesheet. The subfolder AGENTS.md is inline style. The cascade is predictable and intentional.

📋 Starter Template

An effective AGENTS.md doesn't need to be long — it needs to becomplete in the right sections. The Project, Build, Test, Conventions, Constraints, and Context sections cover everything a code agent needs to operate without asking unnecessary questions. A well-structured 200-line file eliminates hours of conversational overhead.

Default template sections

  • #Project— what is the project, language, framework, architecture in summary.
  • # Build— how to build: exact commands, dependencies, order.
  • #Test— how to run tests, minimal coverage, which cannot break.
  • #Conventions— naming, code style, PR standards, commit messages.
  • #Constraints— what the agent should NEVER do (write to /prod, delete bank).
  • #Context— current status, what’s in progress, relevant links.

⚠️ Standard limitations

AGENTS.md is pure markdown, with no required schema, no validation. This is a deliberate choice — simplicity facilitates adoption — but it creates responsibilities that are entirely up to you. Without automatic validation, file quality depends solely on team discipline. Understanding the limitations is essential to not overestimate what the standard delivers on its own.

Real limitations

  • ✗No schema — any format “goes”
  • ✗No linter — you don't know if it's good
  • ✗No semantic versioning of the pattern
  • ✗Silent Drift: Goes out of date without warning
  • ✗There is no guarantee that the agent read

How to mitigate

  • ✓Mandatory review in change PR
  • ✓Monthly update as a routine
  • ✓Test: Ask the agent to summarize AGENTS.md
  • ✓Keep sections named consistently
  • ✓Use separate CHANGELOG.md for history
