📜 CLAUDE.md as traffic control

It's not a diary — it's the document that guides the agent's every decision.

What is it:

Markdown file that Claude Code reads automatically. Defines identity, rules, scope, context.

Why learn:

Without CLAUDE.md, each session starts from scratch.

Key concepts:

Persistent memory, hierarchy (global/project/local), native markdown.

What is it:

Identity, business context, rules, data, standards, decisions already made.

Why learn:

Without structure it becomes a diary; with structure it becomes an operational manual.

Key concepts:

Clear sections, visual hierarchy, examples.

What is it:

~/.claude/CLAUDE.md (global) → project/CLAUDE.md → subfolder/CLAUDE.md.

Why learn:

Allows general rules + override by context.

Key concepts:

Cascade, override, scope.

What is it:

"Always speak in Portuguese", "never commit without reviewing", "no emojis in code".

Why learn:

Defines how the agent responds — tone, format, exclusions.

Key concepts:

Voice, hard rules, exclusions.

What is it:

Too long text, change log, secret data, redundancy with README.

Why learn:

Inflated CLAUDE.md costs tokens in every session.

Key concepts:

Token cost, signal/noise, evolution.

What is it:

With each recurring error, update. For each decision, record it.

Why learn:

It becomes a reflection of the maturity of your system.

Key concepts:

Iteration, learning loop, version control.

🌐 AGENTS.md as multi-vendor standard

Under the Linux Foundation. Used by OpenAI Codex, Google Jules, Cursor, Factory, Amp.

What is it:

Standardized file with context, build steps, tests, conventions for code agents.

Why learn:

Works on Codex, Jules, Cursor, Factory — not just Claude.

Key concepts:

agents.md (website), Linux Foundation, multi-vendor.

What is it:

CLAUDE.md = Anthropic specific. AGENTS.md = open standard. Similar content, different scope.

Why learn:

Knowing when to use which avoids duplication or vendor lock-in.

Key concepts:

Vendor-neutral, override, fallback.

What is it:

Codex assembles chain: global AGENTS.override.md → AGENTS.md → project/AGENTS.md.

Why learn:

Allows CSS-type hierarchy — defaults + overrides.

Key concepts:

Override chain, precedence, defaults.

What is it:

OpenAI Codex (official), Google Jules, Amp, Cursor, Factory. Consolidated standard.

Why learn:

Whoever invests in AGENTS.md today reaps in all agents tomorrow.

Key concepts:

Adoption, ecosystem, future-proofing.

What is it:

Sections: Project, Build, Test, Conventions, Constraints, Context.

Why learn:

Speeds up adoption and avoids zero-symptoms.

Key concepts:

Skeleton, scaffolding, defaults.

What is it:

Pure Markdown, no required fields, no schema validation.

Why learn:

You are responsible for quality — there is no linter.

Key concepts:

No schema, manual review, drift.

🚧 Path-scoped rules

Path-scoped rules. Where pasture becomes a frontier of behavior.

What is it:

"In /clinical/* apply rule X. In /billing/* apply rule Y."

Why learn:

Security applied by architecture, not by twisting.

Key concepts:

Path scope, filesystem ACL, structural enforcement.

What is it:

/data/clinical (PHI), /data/billing (admin), controlled bridge.

Why learn:

Separate domains don't leak by accident.

Key concepts:

PHI, isolation, controlled bridge, audit trail.

What is it:

/data/<domain>/, /summaries/<area>/, /skills/, /agentes/, /logs/.

Why learn:

Convention is the basis of scope.

Key concepts:

Folder convention, naming, separation of concerns.

What is it:

"NEVER read /secrets/*", "ONLY edit /docs/*". Explicit lists.

Why learn:

Reduces impact radius.

Key concepts:

Allow list, deny list, blast radius.

What is it:

/clinical/CLAUDE.md applies rules only within that folder.

Why learn:

Granular override without inflating the root CLAUDE.md.

Key concepts:

Local override, scope, cascade.

What is it:

Bridge controlled with human hook to authorize crossing.

Why learn:

Isolated domains sometimes need to talk—with permission.

Key concepts:

Cross-domain, human approval, audit log.

🔐 Agent Permissions and Jurisdiction

What the agent can touch, read, write. And what needs human approval.

What is it:

Claude Code has modes: confirm each action, accept auto, plan mode, bypass mode.

Why learn:

Defines approval granularity.

Key concepts:

Confirm, auto-accept, plan-mode, bypass.

What is it:

settings.json with whitelists: "Bash(npm:*)", "Edit(src/*)".

Why learn:

Reduces approval prompts for safe, repeatable actions.

Key concepts:

Pattern matching, granular permissions, ergonomics.

What is it:

CFO Bot only plays /finance/. CMO Bot only touches /marketing/. Each has territory.

Why learn:

Defines scope of risk per specialist.

Key concepts:

Agent territory, scope of authority, isolation.

What is it:

Payments, deletions, force-pushes, external communications require confirmation.

Why learn:

"Jagged intelligence" means that even good agents make mistakes in critical things.

Key concepts:

High-stakes, irreversible, human-in-the-loop.

What is it:

Agent runs in container/worktree, without direct access to production.

Why learn:

Errors are contained; rollback is trivial.

Key concepts:

Worktree, container, ephemeral env, rollback.

What is it:

Agent starts with nothing. You release only what is necessary.

Why learn:

It is the basis of any decent security.

Key concepts:

Least privilege, deny-by-default, gradual unlock.

⚖️ Governance as a first-class citizen

Traceability, auditing and compliance are part of the kernel — not optional.

What is it:

Logs, traces and audit trail run inside the agent, not outside.

Why learn:

Bolt-on governance is fragile; built-in scale.

Key concepts:

Built-in × bolt-on, observability-first.

What is it:

Each session produces log: prompts, tools calls, files edited, cost, decisions.

Why learn:

No trail, no accountability.

Key concepts:

Session log, replay, accountability.

What is it:

Path scoping + audit + permissions generate an auditable basis for compliance.

Why learn:

Regulated sectors do not accept "twisting" — they need evidence.

Key concepts:

Evidence-based compliance, controls, mapping.

What is it:

Every irreversible or high-cost action undergoes documented human approval.

Why learn:

"Who authorized it?" there needs to be a clear answer.

Key concepts:

Sign-off, paper trail, four-eyes.

What is it:

Inputs, outputs, prompts, decisions and timestamps in exportable format.

Why learn:

Auditor does not accept “it had worked”. Need evidence.

Key concepts:

Evidence pack, export, tamper-proof.

What is it:

% human approved actions, % with path scope, average time until approval.

Why learn:

Without metrics, governance becomes theater.

Key concepts:

Governance KPI, leading × lagging indicators.

2.6~30 min

🪪 Identity > prompt: the "passwd" of the agentic era

Who is the agent, what is its jurisdiction, what is its scope. Identity comes before any instruction.

What is it:

Prompt = single question. Identity = who he is in every question.

Why learn:

Identity persists; prompt is volatile.

Key concepts:

Persistent identity, ephemeral prompt.

What is it:

"I'm the CFO Bot. I analyze /finance/. I respond within 2 minutes."

Why learn:

Creates clear contract between human and agent.

Key concepts:

Identity card, SLA, scope.

What is it:

Identity = who the agent is. Authentication = how it proves with tokens/keys.

Why learn:

Confusing the two is a classic source of vulnerability.

Key concepts:

Identity × authentication × authorization.

What is it:

A2A standard for agents to advertise capabilities, authentication, endpoints.

Why learn:

It is the future of identity between agents.

Key concepts:

Capability discovery, A2A, agent registration.

What is it:

CLAUDE.md/AGENTS.md in git. Changes go through PR review.

Why learn:

Identity cannot change without a trace.

Key concepts:

Git-backed, PR review, history.

What is it:

Create agent when there is real load and distinct function. Don't create for fashion.

Why learn:

Each agent is operational overhead.

Key concepts:

YAGNI, hire-when-needed, consolidation.
