🎯 Why orchestrator? (90.2% better)

Anthropic measured: multi-agent (Opus 4 lead + Sonnet 4 workers) outperforms single-agent by 90.2%.

What is it:

Anthropic internal assessment: multi-agent outperformed single-agent in 90.2% of search tasks.

Why learn:

It's not hype — it's a reproducible metric in published research.

Key concepts:

Multi-agent research system, eval, parallel exploration.

What is it:

Lead agent decomposes the task, workers execute it in parallel, lead synthesizes it.

Why learn:

Defines the classic division: thinking × doing.

Key concepts:

Plan-execute, decomposition, synthesis.

What is it:

Multi-agent costs ~5-15x more tokens than single-agent. Justifiable when quality matters.

Why learn:

Know when it counts.

Key concepts:

Token cost, value × cost, eval-driven.

What is it:

Without hierarchy, agents overlap. Hierarchy defines who calls who.

Why learn:

Flat line = chaos. Hierarchy = clarity.

Key concepts:

Hierarchy, ownership, accountability.

What is it:

Workers execute subtasks in parallel. Total time ≈ slowest time + synthesis.

Why learn:

Reduces latency without reducing quality.

Key concepts:

Map-reduce, parallel exec, fan-out/fan-in.

What is it:

Simple and well-defined tasks: single-agent is faster and cheaper.

Why learn:

Multi-agent becomes overengineering in 80% of cases.

Key concepts:

YAGNI, simplicity-first, eval before scale.

👔 Chief-of-staff pattern

The EA that receives raw order and routes it to the right specialist. Standard package from Anthropic.

What is it:

Agent that receives requests in natural language, classifies and routes them.

Why learn:

Customer says ONE place; system decides who responds.

Key concepts:

Single entry point, routing, classification.

What is it:

EA uses LLM to classify intent and choose subagent.

Why learn:

Manual routing doesn't scale.

Key concepts:

Intent classification, dispatcher, fallback.

What is it:

Complex question → CFO Bot + CMO Bot + Ops Bot → EA summarizes.

Why learn:

This is what differentiates a chatbot from an orchestrator.

Key concepts:

Chain, fan-out, synthesis.

What is it:

Lists all available subagents, their roles, scope, and SLA.

Why learn:

Without a catalogue, EA doesn't know who to route it to.

Key concepts:

Agent registry, capability catalog, SLA.

What is it:

EA defines timeout per call and plan B (another agent, human).

Why learn:

System without fallback is locked in loops.

Key concepts:

Timeout, retry, fallback, circuit breaker.

What is it:

Every out-of-scope, high-stakes or ambiguous decision scales to humans.

Why learn:

EA knows when NOT to decide.

Key concepts:

Escalation, human-in-the-loop, ambiguity detection.

🤖 Subagents and specialists

CFO Bot, CMO Bot, Ops Bot, Researcher, Builder, Communicator. Each with function, scope and SLA.

What is it:

Name, function, scope, tools, Silver Platters read, expected output.

Why learn:

Standardization allows for reuse and auditing.

Key concepts:

Identity card, scope, deliverable.

What is it:

Read /finance Silver Platters. Margin analysis, cash flow, alerts.

Why learn:

An isolated specialist makes fewer mistakes than a generalist.

Key concepts:

Domain isolation, KPI ownership.

What is it:

Read /marketing — campaigns, audience, voice of the customer.

Why learn:

Marketing requires tone; isolating gives consistency.

Key concepts:

Brand voice, attribution, customer voice.

What is it:

Ops (operations, inventory, logistics), Researcher (discovery), Builder (technical delivery).

Why learn:

It shows that the pattern replicates itself in any function.

Key concepts:

Role taxonomy, agent specialization.

What is it:

Defined in ~/.claude/agents/*.md. Tool Agent invokes by type.

Why learn:

Knowing the syntax allows you to create your own.

Key concepts:

Agents folder, frontmatter, dispatch.

What is it:

Each agent has test cases with expected output. Controlled regression.

Why learn:

Without paper eval, changes in one affect others without realizing it.

Key concepts:

Eval suite, regression test, golden examples.

4.4~45 min

🌐 A2A — Agent-to-Agent Protocol

Google, Apr/2025. 150+ partners. 22k+ stars. Network layer between agents — complementary to MCP.

What is it:

MCP = agent↔tool. A2A = agent↔agent. Different layers, both necessary.

Why learn:

Confusing the two leads to the wrong architecture.

Key concepts:

Tool layer × peer layer.

What is it:

JSON with name, description, capabilities, authentication, endpoint.

Why learn:

It is the "DNS" of the agent network.

Key concepts:

Capability discovery, agent registration, identity.

What is it:

A2A uses HTTP for request, SSE for streaming, JSON-RPC for calls.

Why learn:

Based on web standards — doesn’t reinvent the wheel.

Key concepts:

HTTP, SSE, JSON-RPC 2.0.

What is it:

OAuth, mTLS, signed API keys. Verifiable identity.

Why learn:

Unauthenticated agents are a vector for abuse.

Key concepts:

OAuth, mTLS, signed keys.

What is it:

Agents from different companies negotiating. Agent marketplaces. Federations.

Why learn:

This is where the future of agentic B2B is happening.

Key concepts:

Inter-org, marketplace, federation.

What is it:

SDKs in Python, JS, Java, Go, .NET. Adoption growing in enterprise.

Why learn:

Stay ahead of upcoming integrations.

Key concepts:

Roadmap, SDK, ecosystem.

🧰 Cross-framework standards

LangGraph, CrewAI, AutoGen, OpenAI Agents SDK — they have all converged on the same standard. Know how to translate.

What is it:

Orchestrator as central decision node in graph. Native audit trail and rollback.

Why learn:

Growing enterprise adoption — production at scale.

Key concepts:

DAG, supervisor, state machine.

What is it:

Crew = team. Manager agent coordinates workers. Focus on easy-to-start.

Why learn:

Smoother learning curve than LangGraph.

Key concepts:

Crew, role-based, manager.

What is it:

Microsoft. GroupChat with GroupChatManager. Conversation between agents in rounds.

Why learn:

Good for iterative debate/refinement cases.

Key concepts:

Round-based, debate, refinement.

What is it:

Agent A "passes" control to Agent B. Explicit handoff.

Why learn:

Simple and straightforward pattern.

Key concepts:

Handoff, baton-passing, explicit transfer.

What is it:

LangGraph brain orchestrates crew CrewAI calling OpenAI tools. Blended ecosystem.

Why learn:

It's the future: not choosing a framework, but composing.

Key concepts:

Polyglot, mesh, interop.

What is it:

LangGraph (production, control), CrewAI (quick start), AutoGen (brainstorming), Claude Code subagents (native CLI).

Why learn:

Each case asks for a choice.

Key concepts:

Trade-off, fit-for-purpose.

🚦 When to create (and when NOT to create) agent

Hire-when-needed. Each agent is overhead — only justifiable if there is a real burden and a distinct function.

What is it:

Regular load (weekly+), distinct function, isolated data, measurable eval.

Why learn:

Without criteria, it becomes a collection of useless bots.

Key concepts:

Demand-driven, distinct function, evaluable.

What is it:

"For me to test", obvious overlap, no data, no human owner, no eval.

Why learn:

Resisting temptation saves time and tokens.

Key concepts:

YAGNI, overlap, no-eval = no-go.

What is it:

If 1 skill covers it, it becomes a skill. If it becomes a family of skills + decision, promote to agent.

Why learn:

Promotion avoids initial over-engineering.

Key concepts:

Skill → agent promotion path.

What is it:

Demand fell? Does Eval get worse? Did another cover it? Retire — don’t accumulate zombies.

Why learn:

Complete lifecycle avoids architecture full of ghosts.

Key concepts:

Lifecycle, decommission, sunset.

What is it:

Time saved, human acceptance rate, cost per execution, owner satisfaction.

Why learn:

Without KPI, the decision to maintain/retire is subjective.

Key concepts:

ROI, acceptance rate, cost-per-run.

What is it:

For solo entrepreneur: 3-5 agents. PME: 5-10. Enterprise: 10-30.

Why learn:

Know the healthy size.

Key concepts:

Right-size, lean roster, scaling curve.
