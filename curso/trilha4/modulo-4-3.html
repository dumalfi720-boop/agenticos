🪪 Anatomy of a subagent

Every subagent needs 5 attributes defined before being created. Without them, it fails or overlaps with other agents.The subagent identity is your dedicated AGENTS.md— not the AGENTS.md of the overall project.

🎯The 5 mandatory attributes

  • 1. Function (1 sentence)— "Analyzes financial metrics and produces KPI reports." It must fit in one line.
  • 2. Data scope— Which folders, files and databases it can access. Nothing beyond that.
  • 3. Tools (MCPs)— What tools does it have: SQL, Python, browser, etc. No unnecessary access.
  • 4. Entrance Silver Platters— Which pre-processed summaries he reads for context at no cost.
  • 5. SLA + output format— Maximum response time and the exact format of what you deliver.

💡Minimum Necessary Principle

Each subagent must haveonly the minimum access requiredfor your function. CFO Bot does not need access to the code. CMO Bot doesn't need raw financial data. Narrow scope = fewer errors and more security.

💰 CFO Bot — financial expert

The CFO Bot is the team's financial expert. Heread the /finance Silver Platters, analyzes margins, cash flow and KPIs, and produces structured reports. Domain isolation: it never touches marketing or operations data.

Typical CFO Bot configuration

# AGENTS.md — CFO Bot

## Função
Análise financeira: margens, fluxo de caixa,
alertas de KPI e projeções de curto prazo.

## Escopo de dados
- /finance/silver-platters/ (leitura)
- /finance/raw/ (leitura)
- NUNCA: /marketing/, /ops/, /code/

## MCPs disponíveis
- sql-query (read-only, banco financeiro)
- python-calc (cálculos e gráficos)

## SLA
- Relatório mensal: 120s máximo
- Alerta de KPI: 30s máximo

## Output format
JSON estruturado + texto executivo em pt-BR

Marco uses CFO Bot

Marco (e-commerce) configures CFO Bot to run every Monday at 8am. The bot reads the previous week's data, produces a margin summary by category, highlights the 3 worst performing categories and suggests action. Marco receives the briefing before the management meeting.

📣 CMO Bot — marketing specialist

CMO Bot monitors the voice of the customer, market trends and content performance. Heread Silver Platters from /marketing and /customer-feedback, produces sentiment analysis, identifies churn patterns and suggests experiments.

CMO Bot Knowledge Domain

  • Voice of the Customer:Analyzes support tickets, reviews, NPS for recurring patterns.
  • Content performance:engagement metrics, conversion rates by channel.
  • Competitors:monitors market movements in competitive intelligence Silver Platters.
  • Experiments:suggests A/B tests with hypothesis, metrics and success criteria.

💡Sally Configures CMO Bot

Sally (consultant) uses CMO Bot to audit her clients. Before each monthly meeting, the bot analyzes the client's marketing data and produces a "health report" with 3-5 priority findings. Sally arrives at the meeting with already validated hypotheses — she doesn’t start from scratch.

⚙️ Ops Bot — operations specialist

Ops Bot monitors processes, SLAs, bottlenecks, and operational efficiency. Hereads data from /ops and process Silver Platters, identifies anomalies, calculates capacity and produces contingency plans.

Ops Bot use cases

  • •Supplier SLA monitoring
  • •Detection of bottlenecks in processes
  • •Capacity Planning
  • •Real-time anomaly alerts
  • •Weekly efficiency reports

Typical integrations

  • •Jira / Linear (tickets and sprints)
  • •Notion / Confluence (processes)
  • •Slack (real-time alerts)
  • •Google Sheets (dashboards)
  • •n8n (action automation)

🔧 Implementation in Claude Code

In Claude Code, subagents are implemented asseparate instances with dedicated AGENTS.md per directory. The orchestrator launches subagents via the `Task` tool — each with its own clean context.

Directory structure per agent

projeto/
├── AGENTS.md          # Orquestrador CoS
├── .claude/
│   └── settings.json  # Permissões do orquestrador
├── agents/
│   ├── cfo-bot/
│   │   ├── AGENTS.md  # Identidade do CFO Bot
│   │   └── prompts/   # Templates de análise
│   ├── cmo-bot/
│   │   └── AGENTS.md
│   └── ops-bot/
│       └── AGENTS.md
└── silver-platters/   # Contexto compartilhado (leitura)

How the orchestrator invokes subagents

The CoS uses the toolTaskfrom Claude Code to spawn subagents. Each Task receives: specific context, atomic instruction, expected output format and maximum timeout.

Note: Task tool is available in Claude Code with subagent permission enabled in settings.json.

🧪 Review by subagent

Each subagent needs its own eval — it's not enough to evaluate the system as a whole.Eval by paper isolates where the system is failing: Is it the CFO Bot that got the numbers wrong, or the CoS that gave it the wrong context?

Subagent eval framework

  • Isolation:Test each subagent individually with controlled inputs.
  • Metrics by role:CFO Bot = numerical precision. CMO Bot = relevance of insights. Ops Bot = anomaly detection.
  • Regression:When the system worsens, which subagent caused the deterioration?
  • Latency Benchmark:each subagent has its SLA — it measures whether it is complying.

⚠️Common error: eval only in the final output

Sana only evaluated the system's final report. When the numbers started to go wrong, she didn't know if the problem was the CFO Bot (wrong analysis) or the CoS (wrong synthesis). Without subagent eval, debugging is blind investigation.
