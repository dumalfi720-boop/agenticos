🚦 When to create (and when NOT to create) agent

📋 Criteria for creating an agent

Agent is not synonymous with AI. An agent is aautonomous entity with identity, tools, context and SLA. Creating an agent without any real need is creating complexity that you will keep forever. The creation criteria are strict.

✅The 4 mandatory criteria

  • 1. Actual and recurring load
    The task happens regularly (daily, weekly, at each event). It's not one-off. If it's punctual, use skill or direct prompt.
  • 2. Distinct and non-covered function
    No existing agents cover this role. Creating an agent that duplicates what another already does is waste.
  • 3. Complexity that surpasses skill
    The task requires decision, memory or context that does not fit into a skill. Skills are stateless; agents have been.
  • 4. Definable and measurable SLA
    You can say: “this agent delivers X in Y seconds with Z% accuracy”. Without an SLA, there is no way to know if it works.

💡The right question

Before creating an agent, ask:“Would I need to hire someone to do this full-time?”If so, you can become an agent. If not — if it would be part-time or occasional work — it remains as a skill or prompt.

2

🚫 Signs of NOT creating an agent

As important as knowing when to create is knowing whendo not create. Agent creation anti-patterns are common and costly — every unnecessary agent is maintenance, cost, and complexity that never goes away.

Warning signs (DO NOT create)

  • ✗"So I can have AI in this too"
  • ✗Task happens less than 1x/week
  • ✗Another agent already covers 80% of the case
  • ✗Cannot describe the output in 1 sentence
  • ✗A skill resolves without state
  • ✗Nobody will use the outputs

Alternatives before the agent

  • →Skill in Claude Code (stateless, simple)
  • →Reusable prompt template
  • →Hook that runs existing script
  • →n8n workflow without LLM
  • →Existing agent extension
  • →Silver Platter that another agent reads
3

🪜 Skill → agent: the path to promotion

The correct path is not "create agent from scratch". ANDstart as a skill, promote when justified. Most needs start as simple skills. It only becomes an agent when the skill grows in complexity and the need for state becomes obvious.

The promotion path

  • Level 1Direct prompt— you do it manually, without automation.
  • Level 2Skill— automates the prompt into a reusable slash command.
  • Level 3Skill with context— skill reads Silver Platters for context at no extra cost.
  • Level 4Agent— when the skill became a family of skills + decision between them + persistent state.

Milestone: from prompt to CFO Bot

Marco started by asking for financial analysis manually (Level 1). Created skill/analise-financeira(Level 2). Added /finance Silver Platters reading (Level 3). When the analysis needed to compare with previous weeks and remember alerts, promoted to CFO Bot with state (Level 4). Each promotion was justified by real need.

4

📐 The real cost of an agent

Agents are not free. The cost isn't just tokens — it'smaintenance cost, debugging cost, coordination cost. Before creating, calculate the agent's total cost of ownership (TCO) over time.

Components of an agent's cost

  • Token cost— each execution consumes tokens. Volume × frequency × cost per token.
  • Maintenance cost— AGENTS.md needs updating when the business changes. Estimate: 2h/month per agent.
  • Debugging cost— when it fails, someone needs to investigate. More agents = more points of failure.
  • Coordination cost— the CoS needs to know and manage each added agent.
  • Drift cost— outdated agent silently generates wrong outputs.

⚠️Sana and the Garden of Agents

Sana created 12 agents in 2 months, excited about the possibilities. Six months later: 7 no longer ran due to outdated AGENTS.md, 3 overlapped, 2 worked fine. Cost: 15h/week of maintenance. Expensive learning: an agent that does not have an active owner becomes technical debt.

A healthy operation has aliving inventory of your agents. Which ones exist, which function, who owns it, when it was last updated, what is the estimated monthly cost. Without this inventory, you don't know what you have.

🏁 Hire-when-needed: the ultimate principle

The principle that sums up everything on this trail:hire-when-needed. Agents are like employees — you don't hire ten until you have ten distinct, recurring tasks for ten people. Hire one at a time, when the need is real and continuous.

The final checklist before creating

  • □I tried to solve it with skill first and it wasn't enough?
  • □Does the task occur regularly (≥1x/week)?
  • □Do no existing agents cover this role?
  • □Can I define the SLA in one sentence?
  • □Is there an identified owner who will maintain it?
  • □Is the estimated monthly cost justified by the value?
