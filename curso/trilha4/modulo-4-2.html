👔 Chief-of-staff pattern

The Anthropic pattern: orchestrator as chief-of-staff who never executes directly — only delegates, coordinates and synthesizes. How to structure the lead agent’s identity, responsibilities and limits.

👔 What is chief-of-staff in the agentic context

In human organizations, the chief-of-staffnever performs direct work— it ensures that the right performers receive the right tasks, at the right time, with the right context. The agentic pattern is identical: the orchestrator doesn't do research, doesn't write code, doesn't send emails — he coordinates those who do.

🏗️Agent chief-of-staff responsibilities

  • Receive CEO intent— translate high-level objective into executable tasks.
  • Select the right executor— which expert has the tools and context for each task.
  • Define the done criteria— the worker needs to know when the task is complete.
  • Monitor and react— if a worker crashes or returns inappropriate results, the CoS intervenes.
  • Synthesize and report— consolidates the results into a coherent response for the CEO.

📊Anthropic Model Spec — relevant excerpt

"In multi-agent settings, Claude acting as an orchestrator should focus on decomposition and synthesis. The orchestrator should not attempt to directly execute tasks that subagents are better positioned to handle."

— Anthropic Model Spec, section Multi-agent frameworks (2025)

📝 Orchestrator AGENTS.md

The orchestrator needs a clear identity defined in AGENTS.md. Without that, he tries to do everything himself — destroys the pattern. The file defines:who he is, what he coordinates, what he NEVER does directly, and which agents are under its coordination.

Orchestrator AGENTS.md template

# AGENTS.md — Orquestrador Chief-of-Staff

## Papel
Coordenador central. Recebe objetivos, decompõe em tarefas,
delega para especialistas, sintetiza resultados.

## NUNCA faça diretamente
- Pesquisa de dados ou mercado (→ Researcher)
- Análise financeira (→ CFO Bot)
- Comunicação externa (→ Communicator)
- Execução de código (→ Builder)

## Subagentes disponíveis
- researcher: pesquisa e síntese de informação
- cfo-bot: análise financeira e KPIs
- ops-bot: processos e operações
- communicator: comunicação e relatórios

## Critério de done
Resposta sintetizada cobre todos os subproblemas
definidos no plano inicial.

🔁 The coordination cycle

The chief-of-staff operates in cycles. Each cycle has well-defined phases that do not mix.Mixing the phases is the most common mistake— the orchestrator starts to "help" perform and loses sight of the whole.

The 5 phases of the cycle

  • Phase 1 — Intake:Receive objective. Ask clarifying questions if necessary. Defines scope.
  • Phase 2 — Decomposition:Break into subtasks. Defines dependencies between them.
  • Phase 3 — Dispatch:Sends each subtask to the correct subagent with full context.
  • Phase 4 — Monitor:Follow completion. Handles failures and retries.
  • Phase 5 — Synthesis:Consolidates results. Resolves conflicts. Produces final output.

💡Marco Case: the CoS in action

Marco (e-commerce) asked for "complete analysis to launch the product in the Latin market". CoS intake: scope (3 markets, 2 competitors). Decomp: market research + price analysis + logistical feasibility. Dispatch: 3 workers in parallel. Synthesis in 8 minutes with clear market recommendations.

4

🎯 Smart task decomposition

The chief-of-staff's most critical skill isdecompose well. Bad decomposition creates workers with ambiguous tasks that overlap or contradict each other. Good decomposition creates atomic, independent tasks with clear done criteria.

✓ Good decomposition

  • ✓Atomic task with one responsibility
  • ✓Objective and measurable done criterion
  • ✓No overlap with other tasks
  • ✓Well-defined output (format + content)
  • ✓Independent of other workers

✗ Bad decomposition

  • ✗"Search and analyze and recommend"
  • ✗No defined output format
  • ✗Worker A needs the result from Worker B
  • ✗Vague done criterion ("be complete")
  • ✗Tasks cover the same data
5

🚨 Handling failures and retries

Workers fail. The CoS needs to have a clear failure policy:when to try again, when to escalate, when to accept partial results. Without this policy, a worker failure crashes the entire system.

CoS failure policy

  • Timeout:defines maximum time per worker (ex: 60s). After timeout, mark as "not available".
  • Retry with context:1 retry with additional context before scaling.
  • Fallback:if specialist worker fails, try with generic worker.
  • Partial result:if 4 out of 5 workers conclude, summarize with an "incomplete data" note.
  • Climbing:Critical failures are reported to the user with clear options.

⚠️Anti-pattern: CoS that paralyzes

Sana had her CoS configured to "wait all workers". A worker was in an infinite loop and the entire system crashed for 40 minutes. Mandatory timeout is security setting, not optimization.

6

📤 High-quality synthesis

Synthesis is where the chief-of-staff delivers real value. It's not just "putting the results together" — it'sresolve conflicts, fill gaps, identify patternsthat no single worker saw. This is where CoS justifies its extra cost in tokens.

Components of a good synthesis

  • Conflict Checking:Worker A says X, Worker B says Y on the same data — CoS resolves or signals.
  • Cross Patterns:insights that emerge only when multiple results are viewed together.
  • Prioritization:From the volume of data, the CoS filters what is actionable.
  • Format for the CEO:structures the output in the format the user expects (report, bullet points, decision).

💡The sign of a good synthesis

The synthesis should contain insights that no individual worker could have produced. If the CoS is just concatenating outputs, it's not synthesizing — it's an expensive pipe. The value is in integration, not aggregation.
