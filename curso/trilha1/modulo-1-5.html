📂 P — Prepare

Before any agent, before any skill, before any automation —you need to know where your data is. Preparing is the pantry inventory: mapping sources, identifying systems, understanding formats and defining the source-of-truth of each type of data.

📦The pantry metaphor

A professional chef doesn't start cooking without knowing what's in the pantry. The DISH method uses the same logic:

  • •Font inventory— list all systems: CRM, EHR, spreadsheets, APIs, local files, emails.
  • •Format mapping— CSV, JSON, PDF, XLS, SQL — each requires different treatment.
  • •Source-of-truth identification— when there is conflict, which system wins? Defining this avoids Marco's error.
  • •Quality diagnostics— duplicate data? Outdated? Incomplete? Document before proceeding.

📊P in practice: Marco prepares the SlabHaus

Marco list: Shopify (orders, inventory), Stripe (revenue), Meta Ads (acquisition cost), TikTok Analytics (engagement), Gorgias (tickets). Revenue source-of-truth: Stripe. Customer source-of-truth: Shopify. Conflict identified: shipping is on Shopify and Stripe with different values ​​— Shopify is correct (confirmed with the accountant).

2

📝 R — Summarize

Prepared data is not yet usable data by the agent. The second step istransform raw data into Silver Platters— structured markdown files that the agent can consume in seconds, with the right KPIs, at the right granularity, with defined freshness.

🍽️What is a Silver Plater

A file.mdwhich contains a structured summary of an area of ​​knowledge. Mandatory Features:

  • Clear scope — financeiro.mdHe only talks about finance, never about marketing.
  • Defined freshness— updated daily, weekly or by event. Always with timestamp.
  • Right granularity— KPIs that the decision maker needs, not all available data.
  • Built-in alerts— deviations, anomalies, emergencies — the agent reads and already knows what matters.
# Silver Platter: cliente.md (Marco/SlabHaus)
## Updated: 2026-05-15 08:00

## Whales (LTV > R$5,000)
- Total: 47 customers
- Average purchase: R$ 1,240
- Frequency: 2.3x/month

## Alert
- 12 whales without purchase for >30 days (churn risk)
- Top whale: @usuario_xyz — R$ 18,400 LTV

👔 A — Agency

With data prepared and summaries ready, the third step is to assemble the agentic team.Agency is defining who does what: which experts exist, what is the scope of each one, which tools they have access to, and how the orchestrator coordinates the flow.

🏢Standard agentic structure

EA

EA Orchestrator (Chief-of-Staff)

Receives questions, decides which specialist to call, summarizes results. Read access to all Silver Platters.

CFO

CFO Bot (Finance)

Analyzes P&L, margin, cost. Access:/financeiro/ e /billing/. No access to marketing or operations.

CMO

CMO Bot (Marketing/Customer)

Analyzes engagement, voice of the customer, campaign. Access:/marketing/ e /clientes/. No access to finances.

OPS

Ops Bot (Operations)

Tracks operations, SLAs, suppliers. Access:/ops/. Strict scope.

⚙️ T — Trace

Ready agents still need triggers.Tracing is configuring the hooks and automations that make the work happen without relying on you to remember. SessionStart, PostToolUse, Stop, schedules — these are the autonomic nervous system of your agentic operation.

🔗Types of hooks and their uses

  • PreToolUse— before any tool runs. Ideal for validation, confirmation, audit logs.
  • PostToolUse— after tool runs. Ideal for notifications, updating Silver Platters, alerts.
  • SessionStart— when starting a session. Loads context, updates data, sets state.
  • Stop— when closing. Generates summary, saves decisions, schedules next action.
  • Schedules— cron-like. "Every day at 7am, updates Silver Platters." Invisible work.
# Example: Marco's Sunday hook
# Every Friday at 6pm via schedule
script: consolidate_week.sh
→ Shopify export → normalize → financier.md
→ TikTok export → normalize → marketing.md
→ Notify Marco via Slack with summary

5

🚀 O — Operate

The system is assembled. Now comes the part that most people overlook:put into production with observability and governance. Operating isn't about "plugging in and hoping" — it's about monitoring, evaluating, iterating, and keeping the system healthy over time.

📊What “operate” means in practice

  • Traces in production— every execution recorded. Know what happened, when and with what result.
  • Periodic evals— each week or sprint, review samples of agent responses. Maintained quality.
  • Human validation— for high-impact, human-in-the-loop mandatory decisions. Not as an exception, as a rule.
  • Evolution plan— the system improves. New Silver Platters, new skills, new agents as the business grows.
  • Costs under control— token budget per agent, alert when exceeding threshold.

📈The continuous improvement cycle

1.Run → automatic traces collect quality data
2.Review → evals identify where the agent made a mistake or was inaccurate
3.Diagnose → root of the error: data, prompt, logic or tool?
4.Fix → update Silver Platter, skill or CLAUDE.md as needed
5.Validate → test the fix before going to production
6.Repeat → system gets better with each iteration
