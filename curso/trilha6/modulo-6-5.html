🗺️ Semana 1 — Diagnóstico (Mapa de dados)

A primeira semana não produz nenhum agente — e isso é intencional. Sem um diagnóstico honesto do seu ecossistema de dados, qualquer agente que você construir vai trabalhar no escuro. O entregável obrigatório da semana 1 é o Pantry Inventory completo.

📋 Atividades da Semana 1

D1

Pantry Audit

Liste todas as fontes de dados do seu trabalho. Para cada uma: nome, formato, freshness, owner, volume médio.

D3

Mapeamento Pantry/Prep/Plate

Para cada fonte: onde ela entra no fluxo? É Pantry (bruto), Prep (processado) ou Plate (consumido)?

D5

Quick Wins Identification

Identifique 2-3 tarefas que consomem >2h/semana, têm dados já disponíveis, e são repetitivas. Esses são seus alvos.

💡 Entregável obrigatório: pantry_inventory.md

📄 Semana 2 — Silver Platters + CLAUDE.md (Base limpa)

Com o mapa pronto, semana 2 constrói a base: os primeiros Silver Platters automatizados e o CLAUDE.md raiz do seu projeto. Esta semana é a fundação — tudo que vem depois (skills, agentes, hooks) depende de ter essa base sólida.

⚙️ Atividades da Semana 2

Silver Platters — primeiros 3-5

Para cada Quick Win da semana 1: escreva o script de extração e crie o template .md correspondente. Foco nos dados que já existem e são acessíveis agora.

/resumos/semanal/: vendas_semanal.md, pipeline.md, metricas.md
CLAUDE.md raiz

Escreva as seções obrigatórias: identidade do sistema, fontes de dados disponíveis, regras de nunca fazer, tom de comunicação.

💡 Foundation + automated refresh

O CLAUDE.md raiz é o mais importante que você vai escrever. Ele define o character do sistema. Invista tempo aqui — um CLAUDE.md ruim faz todos os agentes futuros trabalharem com instruções vagas. Um bom CLAUDE.md é explícito: "Quando não souber, diga que não sabe. Nunca invente dados."

# CLAUDE.md — [Seu Projeto]

## Identidade

Você é o assistente operacional de [empresa/pessoa].

## Fontes disponíveis

- /resumos/semanal/ — Silver Platters atualizados toda segunda

## Regras absolutas

- NUNCA acesse /dados/confidencial/ sem confirmação explícita

- NUNCA invente números ou métricas

3

🤖 Semana 3 — Skills + Agentes (Trabalhadores)

A semana que o sistema começa a entregar valor visível. Com a base pronta, você constrói as primeiras skills (comandos slash) e o primeiro agente orquestrador com seus especialistas. Esta semana é onde você vê os Quick Wins virarem realidade.

🏗️ O que construir na Semana 3

2-3 Skills críticas

Escolha as tarefas mais repetitivas dos Quick Wins. Crie um slash command para cada uma. Cada skill deve ter CLAUDE.md próprio.

Exemplo: /weekly-report, /pipeline-summary
1 Orquestrador + 2 Especialistas

Para o seu Quick Win principal, crie a estrutura multi-agente mínima: um agente que recebe a tarefa e dois que executam partes específicas.

Exemplo: EA → CFO Agent + Marketing Agent

📊 First skill, first agent, eval

Após construir a primeira skill, rode-a 3 vezes em dias diferentes. Compare o output com o que você faria manualmente. A avaliação não precisa ser formal — basta responder: "Eu entregaria isso para um cliente?" Se sim, a skill está pronta. Se não, identifique o que falta e ajuste o CLAUDE.md.

4

⚡ Semana 4 — Hooks + Operação (Tornar contínuo)

A semana que transforma um sistema que você opera em um sistema que se opera sozinho. Hooks, crons, e webhooks transformam ações manuais em fluxos automáticos. Observabilidade ativada garante que você saiba quando algo para de funcionar.

⚙️ O que ativar na Semana 4

Cron jobs

Agende os Silver Platters e o relatório principal. Use crontab ou GitHub Actions para ambientes simples.

0 6 * * 1 python3 /scripts/weekly_report.py
Hooks de validação

Adicione verificações pré/pós-run: arquivo de output existe? Tamanho mínimo? Se falhar, notificação imediata.

Observabilidade

Log de cada run com: timestamp, duração, tokens utilizados, status (success/failure). Até um arquivo .log simples serve.

💡 Always-on + observabilidade + iteration

Um sistema always-on sem observabilidade é um sistema que falha silenciosamente. O mínimo de observabilidade: (1) notificação quando um cron falha, (2) log de cada run, (3) dashboard semanal de "quantas vezes rodou vs falhou". Com isso, você sabe o que consertar antes que alguém perceba.

5

🚦 Critérios de Avanço — Sem pular semana

Cada semana tem um gate de avanço: um entregável concreto que precisa existir antes de passar para a próxima etapa. A disciplina de não pular semanas evita o cenário mais comum de fracasso: chegar na semana 4 sem base nenhuma e tentar fazer tudo de uma vez.

✅ Gates de avanço por semana

S1 → S2

pantry_inventory.md existe com pelo menos 3 fontes mapeadas e 2 Quick Wins identificados.

S2 → S3

Pelo menos 2 Silver Platters rodando manualmente + CLAUDE.md raiz escrito com pelo menos 4 seções.

S3 → S4

Pelo menos 1 skill funcionando + 1 agente orquestrador rodando e entregando output aceitável (passou no seu eval).

S4 → ✓

Pelo menos 1 cron rodando automaticamente + log de 3 execuções bem-sucedidas.

📊 Definition of done — sem ambiguidade

O erro clássico é definir "done" como "entendi o conceito" ou "escrevi o código". Done significa: o output existe, está em arquivo, e eu conseguiria mostrar para outra pessoa. Se não existe arquivo com a entrega, você não passou do gate. Simples assim.

6

🚀 Pós-30 dias — Como evoluir

O dia 31 não é o fim — é o início da operação contínua. O Agentic OS é um jogo infinito: a cada quinzena, você adiciona um agente, refina duas skills, e melhora seus evals. O sistema cresce organicamente conforme você identifica novos gargalos.

📅 Cadência de iteração quinzenal

+1
Novo agente
A cada quinzena, identifique 1 tarefa recorrente e crie o agente correspondente.
+2
Skills refinadas
Revise 2 skills existentes com base no uso real. Pequenos ajustes de CLAUDE.md fazem grande diferença.
+1
Eval melhorado
Adicione um critério de avaliação ao relatório de observabilidade. O que você mede, você melhora.

💡 Iteration cadence + kaizen

Empresas como Toyota levaram décadas aprendendo que pequenas melhorias contínuas superam grandes redesenhos esporádicos. Seu Agentic OS segue a mesma lógica: 1% melhor a cada quinzena resulta em um sistema 26% mais eficaz ao fim do ano. Não espere acumular problemas para fazer uma "grande revisão" — itere sempre.
