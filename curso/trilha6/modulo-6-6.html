📁 Estrutura Mínima Viável — O que entregar

O Agentic OS não é um conceito — é uma pasta. A estrutura mínima viável é o conjunto de arquivos e diretórios que precisam existir para dizer que você tem um sistema funcionando. Sem isso, você tem "ideias sobre IA", não um Agentic OS.

📂 Estrutura /agentic-os

/agentic-os/

├── CLAUDE.md # O cérebro do sistema

├── plano_30_dias.md # Seu roadmap preenchido

├── /dados/ # Fontes brutas

│ ├── /fontes/

│ └── /confidencial/ # Se aplicável

├── /resumos/ # Silver Platters

│ └── /semanal/

├── /skills/ # Seus slash commands

│ └── weekly-report.md

├── /agentes/ # CLAUDE.md por agente

│ ├── orquestrador.md

│ └── especialistas/

├── /scripts/ # Automações Python/bash

└── /logs/ # Observabilidade

💡 MVP, boilerplate, deliverable

Cada pasta tem um propósito claro. Não é burocracia — é separação de responsabilidades. Quando um agente falha, você sabe onde procurar o log. Quando quer adicionar uma skill, sabe onde colocar. A estrutura é o que torna o sistema sustentável quando você voltar para ele depois de 2 semanas de férias.

📊 Relatório Semanal Automático — Entrega obrigatória

O entregável símbolo do Agentic OS: um relatório do seu negócio/trabalho gerado automaticamente toda semana, entregue no canal que você preferir (Telegram, email, Slack), sem nenhuma ação sua. Se esse relatório existe e chega pontualmente, você concluiu o curso com sucesso.

⚙️ Arquitetura do relatório semanal

1 0 6 * * 1 — Cron dispara toda segunda às 6h
2 Scripts atualizam Silver Platters em /resumos/semanal/
3 Orquestrador lê Silver Platters + delega para especialistas
4 Síntese gerada → Push para Telegram/email via webhook
5 Log gravado em /logs/YYYY-MM-DD-weekly.log

📊 Cron + push delivery + weekly cadence

Este relatório não é só uma demonstração — é a prova de que o sistema funciona de forma autônoma. Quando você acorda na segunda-feira e o relatório já está no seu Telegram, você sentiu o que Marco sentiu. Essa sensação é o que define a conclusão do curso: não um certificado, mas uma experiência real de autonomia operacional.

✅ Checklist do Projeto — Auto-avaliação

A auto-avaliação final do seu Agentic OS. Seis itens obrigatórios. Cada um representa uma camada do sistema. Quando todos estiverem marcados, você tem um Agentic OS completo — não parcial, não planejado, não "quase pronto".

✅ Os 6 itens obrigatórios

☐
CLAUDE.md raiz

Identidade do sistema, fontes disponíveis, regras absolutas, tom de comunicação. Pelo menos 4 seções.

☐
3 Silver Platters automatizados

Scripts rodando, arquivos .md gerados em /resumos/semanal/. Cada um atualizado automaticamente.

☐
1 skill funcionando

Slash command que você usa pelo menos 3 vezes/semana e que já passou no seu eval pessoal.

☐
1 orquestrador com especialistas

Agente principal que delega para pelo menos 2 agentes especialistas e sintetiza resultados.

☐
1 hook de validação

Verificação automática pós-run que confirma que o output existe e notifica em caso de falha.

☐
1 cron funcionando

Pelo menos o relatório semanal rodando automaticamente. Log de 3 execuções bem-sucedidas em /logs/.

💡 Checklist + definition of done

Este não é um checklist de certificação — é um checklist de utilidade. Cada item existe porque representa uma parte do sistema que gera valor real. O CLAUDE.md sem o cron é um manual sem execução. O cron sem o CLAUDE.md é automação sem inteligência. Os seis juntos são o sistema.
