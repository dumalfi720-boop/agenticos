🍳 Pantry / Prep Table / Plate — data map

The kitchen metaphor that organizes where data lives, where it is processed and where it becomes action. Visual framework to map any agentic data operation.

🥫 Pantry — where data lives

A PantryIt's the kitchen stock. These are databases, external APIs, spreadsheets, log files, SaaS systems — thesource of truththat exists independently of agents. The data in Pantry is the real data, without transformation.

🥫What lives in the Pantry

  • •Relational banks— PostgreSQL, MySQL, BigQuery. Transaction tables, customers, products.
  • •External APIs— Meta Ads, Google Analytics, Shopify, Stripe, HubSpot.
  • •Static files— Export CSVs, contract PDFs, legacy spreadsheets.
  • •Work tools— Notion, Drive, iManage, ERP/EHR systems.
  • •Event Streams— Kafka, Kinesis, real-time application logs.

💡Rule: Pantry is not touched by the agent

Agents should not read directly from Pantry in production, except via MCP Server with explicit read-only permission. Direct access creates weak coupling and exposes sensitive data without context control.

2

🔪 Prep Table — where data is prepared

A Prep Tablethis is where the sous-chef works before service. It is the ETL, cleaning, aggregation and summarization layer.It's the context factory— what comes out of here are Silver Platters ready for consumption. Everything here is deterministic and auditable.

🔧Prep Table Operations

  • Extraction (E)— read Pantry via API, SQL query, file reading.
  • Transformation (T)— calculate KPIs, normalize units, detect anomalies with threshold.
  • Load (L)— write Silver Platter to the filesystem with timestamp and TTL.
  • Summarization— optional: LLM generates the narrative text AFTER Python calculates the numbers.

🛠️Typical Prep Table Stack

  • Python + pandas— local processing, cron scripts.
  • dbt— versioned SQL transformations, ideal for data teams.
  • n8n/Make— visual orchestration when there is no engineering team.
  • Cron/Airflow— automatic platter regeneration schedule.
3

🍽️ Plate — where data becomes action

O platethis is where the dish is served. This is where the prepared Silver Platter becomes an executive brief, a communicated decision, triggered automation, or a sent report.Without a Plate, of course, data does not become action— it remains as a report that no one reads.

🎯Plate Shapes

  • •Executive brief— agent reads platters and generates email/Slack with recommended decisions.
  • •Automatic alert— n8n reads platter, detects anomaly, triggers notification.
  • •Live Dashboard— platter feeds the panel that the manager opens in the morning.
  • •Automated action— platter detects bad campaign, pauses automatically via API.
  • •Input for expert agent— platter is injected into the system prompt of the CFO/CMO agent.

⚠️Plate without recipient

The most common mistake: building the entire kitchen (Pantry + Prep Table) and not defining who receives the dish. Every Prep Table needs a clearly specified Plate: who receives it, when, in which format, with which update SLA.

Before building any agent,draw the kitchen diagram. Three columns: Pantry, Prep Table, Plate. Connections between sources, transformations and outputs. This eliminates ambiguity and reveals where dependencies and bottlenecks are.

💡How to use the diagram

Build the diagram BEFORE writing any code. Show it to the customer and ask, "Is this your kitchen?" Often the answer reveals hidden sources, duplicate data and Plates that never reach the right destination.

5

⏱️ Latency by stage

Each kitchen stage has a different latency and a different update model.Identify where the bottleneck isIt’s the first step to optimizing — the problem isn’t always the Prep Table. Sometimes it's Pantry that doesn't update.

⏱️Typical latency by stage

Pantry Real-time to daily External APIs vary: Shopify has webhooks (real-time), Meta reports have a 3h delay.
Prep Table 1 min to 1 day It depends on the volume. Lightweight CSVs: seconds. BigQuery with joins: minutes. Historical reprocessing: hours.
plate Seconds Agent reads Silver Platter and generates response in seconds. The dish served is quick — the prep is what took time.

📊Batch vs Stream

  • Batch (cron)— suitable for daily KPIs, weekly reports. Simple, auditable.
  • Stream (Kafka, webhooks)— needed for real-time alerts, fraud detection, monitoring.
  • Rule— start batch. Only upgrade to stream when the required TTL is less than 1 hour.

📦 Applied to personas: Marco, Sally and Sana

Each persona has a different cuisine. Same conceptual structure — Pantry, Prep, Plate — but with completely different ingredients, processes and dishes.Seeing the method applied anchors learning.

🛒 Marco — E-commerce

  • Pantry:Shopify, Meta Ads, Google Analytics, inventory spreadsheet.
  • PrepTable:Python calculates CAC, ROAS, inventory turnover. Cron at 07:00.
  • Plate:Daily Brief on Slack + CMO Bot receives platters at system prompt.

⚖️ Sally — Lawyer

  • Pantry:iManage (documents), Outlook (emails), contract system, case law basis.
  • PrepTable:When opening a new process: extracts relevant docs, summarizes via LLM, chronological structure.
  • Plate:Case scaffold: parts, timeline, arguments, next actions. Injected into the Research Agent.

🏥 Sana — Doctor

  • Pantry:EHR (clinical history), test reports, previous prescriptions, allergies.
  • PrepTable:When opening a query: extracts relevant history, groups by system, formats for quick viewing.
  • Plate:Clinical summary of the current consultation: context, findings, differential hypotheses to check.
