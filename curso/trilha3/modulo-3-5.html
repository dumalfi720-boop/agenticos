📚 Why prompt engineering became obsolete

Prompt engineering was the discipline of a single prompt— you wrote an instruction and received a response. It was enough for chatbots.Agents make hundreds of calls in a row: search files, run tools, call subagents, summarize results. Prompt engineering doesn't scale for this.

🔄The evolution of disciplines

2022-2023
Prompt Engineering— write the right prompt for 1 call. Zero-shot, few-shot, chain-of-thought.
2024
RAG Engineering— retrieve the right documents to enrich the prompt. Embeddings, vector search.
2025-2026
Context Engineering— manage what information enters the window, when, in what format, during long-running agent loops.

📊Anthropic, September 2025

"Context engineering is the practice of carefully crafting and managing information in the context window to produce specific behaviors from AI systems."

— Official Anthropic documentation, Sep/2025.

2

🪟 Context window as a scarce resource

The context window is not infinite — each token takes up space, costs money, andcompetes for attention with all other tokens. Noisy window dilutes the signal of important instructions. Well-managed window = more accurate and cheaper agent.

💰Token economy in practice

  • •Claude Sonnet 4.5— 200K context tokens. ~150K words. It seems like a lot, doesn't it.
  • •1 5MB CSV— easily 500K+ tokens. It doesn't fit. Need Silver Platter.
  • •Long shoot without pruning— tool call history accumulates. Performance degrades after ~50 turns.
  • •Actual cost— agent that processes 1M tokens/day × R$0.003/1K = R$3,000/month in input alone.

⚠️Attention dilutes with inflated context

Research from Anthropic shows that instructions in the middle of a very long context receive less attention than instructions at the beginning or end. "Lost in the middle" is real.Smaller context, with purer signal, produces better responses.

🎯 Just-in-time Context

Instead of injecting all the information at the beginning of the session, the agent loads what it needsat the moment you need. The analogy is lazy loading of code: you don't load the entire module, you load the function when it is called.Paths instead of content— the agent reads the file when necessary.

⚡Just-in-time standard

✗ Eager loading (bad)

System prompt com:
- marketing.md completo
- financeiro.md completo
- operacoes.md completo
- historico.md completo
Total: 40K tokens antes de
o agente fazer qualquer coisa

✓ Just-in-time (good)

System prompt com:
- Paths dos platters disponíveis
- Instrução: "leia o platter
  relevante antes de responder"
Total: 500 tokens. Agente lê
só o que precisa, quando precisa

💡CLAUDE.md as index

The project's CLAUDE.md is the natural implementation of just-in-time context. It doesn't load all the code — it lists where the important files are and when to read each one. The agent navigates on demand. This is the reason why CLAUDE.md works best when it is a lean index, not a documentation dump.

🗂️ Compaction and Pruning

Long sessions accumulate garbage: verbose tool outputs, intermediate messages, obsolete context.Without compression, the session degenerates— the agent begins to lose the thread, repeat information or ignore old instructions. Compaction is active quality maintenance.

✂️What to compress

  • •Long tool outputs— search result with 200 items → summarize to the 5 relevant ones.
  • •Reasoning history— intermediate thoughts after a decision has been made.
  • •Obsolete context— information about a previous version of the problem that has already been resolved.
  • •Reference files read— after extracting what was needed, remove the raw content.

⚙️Automatic compression in Claude Code

Claude Code has automatic compression configurable via hooks:

# settings.json — hook pós-compactação
{
  "hooks": {
    "PostCompact": [{
      "matcher": ".*",
      "hooks": [{
        "type": "command",
        "command": "echo 'Contexto compactado. Verifique CLAUDE.md.'"
      }]
    }]
  }
}

⚡ Prompt Caching — TTL of 5 minutes

Anthropic keeps the prompt prefix in cache for 5 minutes — and charges90% lessby tokens served from the cache. For agents that process many calls with the same context system (CLAUDE.md, Silver Platters, identity), the cache is automatically gained if the structure is correct.

💰How caching works

  • •Stable prefix— what comes before the cache point does not change between calls.
  • •cache write— first call pays normal price + small writing fee.
  • •cache hit— subsequent calls within 5 minutes pay 10% of the original price.
  • •Discount in practice— CLAUDE.md of 10K tokens × 100 calls/day = R$X vs R$X/10.

📐Context order for maximum cache hit

1 System/identity(more stable — rarely changes)
2 Silver Platters / base context(changes daily)
3 Conversation history(changes every turn)
4 User message(more dynamic — never curly)

📐 Anthropic’s Three Rs

In September 2025, Anthropic published the principles of Context Engineering in three simple rules:Right Context, Right Time, Right Format. A heuristic that fits in your head and covers 90% of context design decisions.

📐The Three Rs

1. Right Context

Only what is relevant to the current task. Not "everything that might be useful" — whatéuseful now.

Example: To analyze marketing campaign, inject marketing.md — not financial.md, not contracts.md.

2. Right Time

Upload when the agent needs it, not before. Just-in-time, not eager loading.

Example: Customer-specific Silver Platter → load when the agent opens that case, not at the beginning of the session.

3. Right Format

Structure that the agent parses efficiently. Structured Markdown > free text. Tables > paragraphs for numeric data.

Example: KPIs in a Markdown table, not in a narrative paragraph — the agent extracts numbers more precisely.

💡Applying the Three Rs

Before each context decision, ask: "Is this the right data? Am I loading it at the right time? Is the format what the agent processes best?" If the answer is "no" to either, redesign before scaling.
