📜 What is MCP

Model Context Protocolis an open standard created by Anthropic in November 2024 to connect agents to tools, databases and external data. Before MCP, every integration was custom — new code for each new tool.MCP standardizes this conversation, like USB standardized peripherals.

🔌Analogy: MCP as USB

  • •Before USB— each peripheral had a different connector. PS/2 printer, serial mouse, AT keyboard.
  • •After USB— a pattern. Any peripheral, any computer.
  • •Before MCP— each integration was custom code. GitHub, Slack, Notion: different API for each.
  • •With MCP— a protocol. Any tool with MCP Server connects with any MCP Client agent.

🔌 Technical anatomy: Server, Client, Transport

MCP has three main components.Serverexposes capabilities (tools, data, prompts).Clientit is the agent that calls the server.TransportIt is the means of communication between them. Understanding this triad is a prerequisite for using or building any MCP integration.

🏗️The three components

MCPServer

Separate process that exposes capabilities via standardized protocol. It can be local (your computer) or remote (cloud). Responsible for authentication, rate limiting, security of exposed data.

MCP Client (Agent)

Claude Code, Cursor, or any agent that implements the MCP client protocol. Discover the server’s capabilities viatools/list, then invoke viatools/call.

Transport

studio— for local servers (child process). Simpler, without network overhead.
SSE (Server-Sent Events)— for remote servers, event streaming.
Streamable HTTP— new standard (2025), more robust for production.

💡When to use which transport

Usestudiofor local development and personal scripts. UseSSE/HTTPwhen the server needs to be shared with a team or run in the cloud. Marco and Sally use local stdio servers; a company with a team of 20 people needs a centralized HTTP server.

🛠️ Tools, Resources and Prompts

MCP defines three types of capabilities that a server can expose. Knowing when to use each avoids common anti-patterns — like exposing a destructive action as Resource instead of Tool, or duplicating data unnecessarily.

🎯The 3 types of capability

🛠️ Tools — actions that the agent performs

Operations with side effects: creating an issue on GitHub, sending a message on Slack, updating records in the CRM.

tool: create_github_issue(title, body, labels) → issue_url

📖 Resources — data that the agent reads

Static or dynamic content that the agent can consume: files, documents, bank data. No side effect.

resource: file://platters/marketing.md → conteúdo do arquivo

💬 Prompts — reusable templates

Parameterized instructions that the server offers to the agent. Analogous to skills, but served by the server.

prompt: analise_campanha(periodo="7d") → instrução montada

✓ Use Tool when

  • ✓The operation changes state (create, edit, delete)
  • ✓Need confirmation before running
  • ✓Returns execution result, not data

✓ Use Resource when

  • ✓Only read existing data
  • ✓Content may be cached
  • ✓Safe to invoke multiple times (idempotent)

🏗️ Building your own MCP Server

When community servers don't cover your internal systems, you build your own.Every serious internal system deserves an MCP server— Own ERP, internal database, legacy API. With FastMCP (Python) or the official SDK this takes hours, not weeks.

🐍Example: MCP Server with FastMCP (Python)

from fastmcp import FastMCP
import pandas as pd

mcp = FastMCP("Servidor de Vendas Marco")

@mcp.tool()
def consulta_kpis(periodo: str = "7d") -> dict:
    """Retorna KPIs de vendas do período especificado"""
    df = pd.read_csv('vendas.csv')
    # filtrar por período, calcular KPIs
    return {
        "receita": df['valor'].sum(),
        "pedidos": len(df),
        "ticket_medio": df['valor'].mean()
    }

@mcp.resource("platter://marketing")
def marketing_platter() -> str:
    """Retorna o Silver Platter de marketing atual"""
    with open('platters/marketing_current.md') as f:
        return f.read()

if __name__ == "__main__":
    mcp.run()  # stdio por padrão
