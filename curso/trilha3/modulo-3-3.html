🛠️ Skills as living processes

Skill is not prompt. It is a reusable process with input, steps, output and examples. The engineering of building capabilities that the agent executes on demand — and that improve with use.

📜 What is a Skill

OneSkillis a reusable process declared in Markdown — with expected input, steps to follow, defined output, and examples. In Claude Code, she becomes aslash command: you type/formato-cursoand the agent executes the complete process. It's the opposite of ordering everything from scratch every time.

🔑Skill vs Prompt: fundamental difference

  • Prompt— single instruction, forgotten after the response. No structure, no example, no reuse.
  • Skill— persistent document with declared behavior. The agent reads it and executes the complete process, every time it is invoked, with the same quality.
  • Result— skill guarantees consistency that prompt does not guarantee. It’s the difference between a verbal request and a written SOP.

💡When to create a skill

If you've asked the agent for the same thing more than three times, it's time to code it as a skill. Marco uses/analise-campanhaevery week. Sally uses/scaffold-casoevery time you open a process. Sana uses/sumario-clinicoat the beginning of each consultation.

2

🛤️ Skill critical path

O critical pathit's the sequence of steps that always works — no deviations, no improvisation. It's the result of iteration: you test, observe where the agent stumbles, refine the steps until the happy path is solid.Without an explicit critical path, the agent wastes time exploring.

🗺️Example: critical path of /scaffold-case (Sally)

1 Read CLAUDE.md to check the office context and active persona.
2 Request: case number, parties, type of action, distribution date.
3 Create folder structure: /cases/[number]/briefing.md, /docs/, /prazos.md.
4 Fill in briefing.md with parts, requests, timeline, next actions.
5 Confirm with Sally: "Scaffold created. Do you want to add initial documents?"

📐 Anatomy of a Skill

Well-built skills havepredictable structure: frontmatter with metadata, body with instructions, usage examples. The agent learns to anticipate what it will encounter — and executes with more precision. Standardization allows auditing and reuse.

📄Canonical skill template

---
name: analise-campanha
description: Analisa performance de campanhas de mídia paga e gera recomendações
trigger: /analise-campanha
inputs:
  - silver_platter: marketing.md (obrigatório)
  - periodo: últimos 7 dias (padrão)
outputs:
  - análise narrativa com dados
  - 3 recomendações priorizadas
  - 1 alerta se ROAS < 2.5x
when_to_use: Toda segunda-feira ou após pedir revisão de campanha específica
---

## Instruções

1. Ler `platters/marketing_current.md`
2. Verificar timestamp — se > 24h, alertar antes de continuar
3. Identificar as 3 campanhas com pior ROAS
4. Comparar com benchmark da semana anterior
5. Gerar análise em 3 parágrafos: contexto, achados, recomendações
6. Se ROAS geral < 2.5x, incluir alerta explícito no topo

## Exemplos

Input: "analise as campanhas de Black Friday"
Output esperado: Análise com dados reais do platter, não estimativas

🔁 Skill like infinite game

You never finish a skill — youiterates forever. Each use reveals an edge case. Each error is input to improve the next step.The “one and done” mentality is the biggest enemy of agentic quality. Skills are living documents, not frozen code.

🔄Iteration cycle

To write Minimum skill with the happy path. Without trying to cover everything.
To use Invoke the skill 5-10 times in real scenarios.
Observe Where does the agent improvise? Where does it hang? What did the output get wrong?
Refine Add explicit step to cover the observed error.
Repeat Return to "Use". Endless. It's an infinite game.

💡Skill versioning

Skills live in the filesystem with git. Every change is a commit with clear message: "adds TTL check before parsing". History is the learning log of the operation.

📦 Portability: Claude Code vs Codex vs others

The concept of skill is convergent —multiple platforms are adopting variantsof the same pattern. But the syntax varies. Knowing the differences allows you to port skills between environments without rewriting everything from scratch.

🔄Platform comparison

Claude Code (.claude/skills/)

Markdown files with YAML frontmatter. Activated via/nome-da-skill. Support for tools, MCP, hooks, hierarchical context.

OpenAI Codex/Agents SDK

Declarative instructions in agent systems. Similar concept, but without native slash commands — requires explicit orchestration via SDK.

Cursor / Windsurfing Rules

Files.cursorrules ou .windsurfrules— rules of behavior, analogous but without structured examples.

⚠️Vendor lock-in trap

Skills written with excessively proprietary syntax make portability difficult. Write the body of instructions in pure, universal Markdown. Only the frontmatter should have platform-specific fields.

🧪 Skill ↔ Test

Untested skill regresses silently. A change in skill to cover a new case breaks an old case — and you only find out when the agent makes a mistake in production.Each skill must have example cases with expected output. Automated eval when possible.

🧪Skill testing framework

## Casos de Teste — /analise-campanha

### Caso 1: platter fresco, ROAS saudável
Input: marketing_current.md (timestamp hoje, ROAS 3.2x)
Output esperado:
  ✓ Análise menciona ROAS de 3.2x
  ✓ Sem alerta de ROAS
  ✓ 3 recomendações presentes
  ✗ NÃO deve inventar números

### Caso 2: platter velho (> 24h)
Input: marketing_current.md (timestamp 48h atrás)
Output esperado:
  ✓ ALERTA de dado desatualizado no início
  ✓ Análise continua, mas com ressalva explícita

### Caso 3: ROAS abaixo do threshold
Input: marketing_current.md (ROAS 1.8x)
Output esperado:
  ✓ ALERTA de ROAS crítico no topo
  ✓ Recomendações mais urgentes (pausar, revisar)

💡Automated Eval

For critical skills, create a Python script that runs the skill with known fixtures and checks if the assertions pass. It doesn’t have to be perfect — checking the 3-5 most important assertions already captures 80% of regressions.
