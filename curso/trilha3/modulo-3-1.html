📋 What is a Silver Platter

Um silver plateis a structured text file — usually Markdown — that summarizes a business area in a format ready for consumption by agents. It is preprocessed by humans or deterministic code, not generated on-the-fly by LLM.The tray is ready: you put it in front of the agent and it has everything it needs to reason without having to scan raw files.

🍽️The tray metaphor

Imagine a chef. He doesn't go to the market during the service — the mise en place is already ready. Silver Platter is the agent's mise en place:

  • •Data already processed— numbers calculated by Python, not estimated by LLM.
  • •Predictable structure— the agent knows exactly where to find the sales KPI.
  • •Relevant context— just what the agent needs, without the noise of irrelevant files.
  • •Explicit timestamp— the agent knows whether the data is from today or a week ago.

📊Why does this matter

Without Silver Platters, agents make predictable mistakes:

  • Numerical hallucination— LLM invents KPIs that don't exist in the raw data.
  • Loss of context— context window explodes trying to read entire CSVs.
  • Outdated data— agent uses training memory, not real business data.
  • Latency— each call needs to reprocess everything from scratch.

🔄 Gross → Silver Platter → Agent

The flow has three clearly separated stages.Raw data(sales.csv, campaigns.xlsx, contracts.pdf, system logs) go through apreparation stage(Python, SQL, scripts) and generate structured Silver Platters that the agent consumes. These stages should not mix.

1

Raw Data (Pantry)

Original sources — do not directly touch the agent context

sales.csv, meta_ads.json, contracts.pdf, spreadsheet_rh.xlsx, logs.jsonl — data as it came from the systems.

2

Preparation (Prep Table)

Python, SQL, deterministic scripts — never LLM for numbers

# Exemplo: gerar silver platter de marketing
df = pd.read_csv('meta_ads.csv')
kpis = {
  'cac': df['gasto'].sum() / df['conversoes'].sum(),
  'roas': df['receita'].sum() / df['gasto'].sum(),
  'melhor_campanha': df.sort_values('roas').iloc[-1]['nome']
}
# Escreve o .md com timestamp
write_platter('marketing.md', kpis, datetime.now())

Silver Platter (Plate)

The .md file that the agent reads — compact, accurate, timestamped

marketing.md, finance.md, operations.md, cliente.md — one file per domain.

📐 Standard structure of a Silver Platter

A well-structured Silver Platter has fixed sections that the agent learns to navigate. Without standardization, each platter becomes a surprise — the agent wastes time inferring where the data is.Implicit schema is technical debt.

📄Canonical template

# Silver Platter: Marketing
**Gerado em:** 2026-05-15 08:00 BRT
**Fonte:** meta_ads.csv, google_analytics.json
**TTL:** 24h (regenerar às 07:00)

## Resumo Executivo
CAC atual: R$ 87 (meta: R$ 90 ✅)
ROAS: 3.2x (meta: 3.0x ✅)
Leads mês: 1.847 (meta: 2.000 ⚠️)

## KPIs Principais
| Métrica | Valor | Δ vs mês ant | Status |
|---------|-------|--------------|--------|
| CAC | R$87 | -8% | ✅ |
| ROAS | 3.2x | +5% | ✅ |
| CTR | 2.4% | -0.3pp | ⚠️ |

## Alertas
- CTR caindo há 3 semanas seguidas
- Budget de remarketing 92% consumido

## Oportunidades
- Campanha "Verão" tem ROAS 4.1x — candidata a escalar

## Perguntas em Aberto
- Por que CTR caiu em mobile específico?

💡Rule of thumb

The Executive Summary should be sufficient for 80% of the questions. The following sections are drill-down. Marco (e-commerce) uses this framework for his CMO Bot to consume every morning without relying on raw data from Shopify.

4

🤖 Deterministic vs Generative

There is a clear line that separates what must be calculated by code and what can be generated by LLM.Numbers are deterministic— Python calculates, never LLM.Narrative is generative— the LLM interprets and explains the calculated numbers.

✓ Python/SQL does

  • ✓Sum of revenue, CAC, ROAS
  • ✓Record count, averages, percentages
  • ✓Campaign ranking and ordering
  • ✓Anomaly detection with fixed threshold
  • ✓Timestamp and TTL

✗ LLM DOES NOT calculate

  • ✗Add CSV rows directly
  • ✗Infer KPIs without structured data
  • ✗Estimate percentages "in your head"
  • ✗Decide if data is up to date

💡What the LLM does well in the Silver Platter

After Python fills in the KPIs, LLM writes the "Executive Summary" in natural language, identifies patterns between metrics, and generates the "Open Questions." Clear division: code computes, LLM interprets.

5

⏰ Freshness, TTL and Versioning

A Silver Platter without a timestamp is a time bomb.Old data kills analysis— the agent responds safely using obsolete information. Each platter must explicitly state when it was generated and when it expires.

📅TTL by data type

  • •marketing KPIs— TTL 24h. Cron 07:00 daily.
  • •Sales pipeline— TTL 4h. Cron every 4 hours on weekdays.
  • •Financial report— TTL 7 days. Generated on Fridays after closing.
  • •Client Briefing (Sally)— TTL per case session. Regenerated when opening a new process.
  • •Clinical summary (Sana)— TTL per visit. Regenerated with each new query.

📊Simple versioning

No git required for platters. Sufficient standard:

platters/
  marketing_20260515_0800.md   # versão com timestamp
  marketing_current.md          # symlink para o mais recente
  marketing_20260514_0800.md   # versão anterior (retenção 7 dias)

🌟 Karpathy LLM Wiki — the evolved version

Andrej Karpathy proposed in 2025 that agents should maintain aviva Markdown wiki— compiled incrementally with each new observation. It is the Silver Platter that is self-enriching: entities, contradictions, syntheses and cross-links grow with use.

📖Difference: Static Platter vs Living Wiki

  • •static platter— generated by script, replaces the previous one. Snapshot.
  • •LLM Wiki— the agent reads new data andupdatethe relevant page, preserves history.
  • •Cross-links— "Campaign A → related to Client B → see also: Contract C".
  • •Contradictions tracked— when new data contradicts old data, the page records the conflict.

💡When to use which

Static Silver Platters for repetitive operations (daily reports, weekly KPIs). LLM Wiki for entity-rich domains with long history — legal cases (Sally), clinical history (Sana), client portfolio (Marco). Start with Platters, evolve to Wiki when the volume of entities grows.

⚠️Wiki trap without governance

Wiki without TTL and without curator becomes a swamp. Define: who can write, what TTL per page, how to resolve conflict. Without this, the agent relies on contradictory data and quality silently degrades.
